## 2. 事实源规则

1. 产品范围以 PRD 为准；功能编号以功能点清单为准。
2. 架构变更必须先写 ADR，再改代码；ADR 未接受前只能做原型。
3. “已完成”必须附代码位置、测试命令或手工证据；没有证据写“未验证”。
4. 不把 mock、fixture 或 UI 占位当成真实捕获/真实检测。
5. 不能可靠判断回复结束时，产品显示 `Unknown`；文档不得把 `Unknown` 写成“已完成”。
6. 任何新增网络、遥测、持久化截图或第三方 API 的能力，都需要 owner 明确同意。

## 3. 状态词

| 状态 | 含义 |
|---|---|
| 草案 | 已写出，但未拍板 |
| 已确认 | Owner 已同意，可作为实现依据 |
| 实现中 | 代码在写，尚未达到验收 |
| 已验证 | 有可复现命令或手工证据 |
| 已放弃 | 明确不做，保留原因 |

## 4. 更新规则

- 每个里程碑结束：更新 `03`、`04`、`handoff.md`。
- 新决策：先加 ADR，再改 PRD/架构中的相关段落。
- 新风险：写入 `08`，不要只留在聊天记录。
- 发布前：复核 `07` 的签名、权限、隐私和分发检查单。
- 对外文案与演示：以实际可运行状态为准，不提前写成“已支持”。
