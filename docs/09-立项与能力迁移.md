## 1. 立项信息

- **产品名**：Argus（内部定名，2026-11-21）。
- **Tier**：Tier 2（一般项目）。
- **仓库**：<https://github.com/bayernjf/argus>（public）。
- **平台**：首版只做 macOS 14+；Windows 在后续迁移阶段再单独立项。
- **产品形态**：菜单栏/Dock 打开的 Dashboard，可同时监控多个目标软件；
  每个目标软件对应一张监控卡片。

## 2. 核心功能

1. 每张监控卡片实时捕获对应目标软件的窗口内容。
2. 判断目标软件中的 AI 回复是否已经结束，支持流式输出完成检测。
3. 每张卡片显示目标窗口的小缩略图；点击缩略图切换到对应目标软件窗口。

产品边界、非目标和验收细节以 `01-PRD-产品需求规格.md` 为准。

## 3. 能力迁移

### 3.1 现状

- `one-code` 仓库：<https://github.com/bayernjf/one-code>（public，TypeScript）。
- 2026-11-22 评估了其状态聚合、探针、配置校验与活动历史实现。
- **当前结论：暂不借鉴，先专注 Argus 自身的真实客户端标定与 M4 稳定性。**
- 未引入任何 `one-code` 依赖、代码或运行时路径；其 GitHub 元数据未声明 SPDX
  许可证，代码不可直接复制。
- 相关风险与开放问题见 `08-风险与开放问题.md` 的 R-12。

### 3.2 借鉴评估（仅记录，暂不实施）

| 候选点 | `one-code` 做法 | 对 Argus 的潜在价值 | 对现有功能的破坏风险 | 若将来实施的安全路径 | 当前决定 |
|---|---|---|---|---|---|
| 信号权威性 | `SignalAuthority` 区分 `session`（宿主明确告知）与 `heuristic`（静默/频率/文本推断）；session 工作期间 heuristic `done` 不抢通知 | 把 AX Stop 的“确定生成”与 OCR/视觉的“推断完成”分层，降低高置信误报 | 低；只加可选字段与仲裁规则 | 默认保持现有行为；先补 characterization fixture；AX 仅做确定性 generating 否决，不把“没看到 Stop”当完成 | 暂缓 |
| 每信号独立状态再聚合 | 每个 `MonitorSource` 独立 `SessionState`，再按 `waiting > working > done` 聚合 | 视觉/OCR/AX 各自保留健康状态，单信号失败不拖垮整体 | 高，若直接重写 analyzer 会改 OCR/AX 频率、完成时延与竞态 | 保留 `ReplySignalAnalyzer` facade，内部拆 probe；外部签名与阈值不变；先跑正负 fixture 对比时间线 | 暂缓，M4 后再评估 |
| 本地转换历史 | `activityLog` 存最多 200 条完成/等待事件，含来源与时长，可统计/导出 | M4 诊断“为什么 Completed”，定位 OCR 失联/AX 消失/settle 到期 | 低；独立内存环形缓冲 | 只存目标 UUID、phase、时间、confidence、source、AX 是否 measured；不存正文/标题/截图；不落盘 | 可作 M4 诊断候选，尚未排期 |
| 配置校验与自愈 | 写入侧拒绝非法模式，读取侧隔离脏配置，避免重启崩溃循环 | 为未来 Profile 持久化提供防崩边界 | 中；错误 Profile 会改变检测行为 | 独立 `reply-profiles.json`、版本化、逐字段校验、非法回退 `generic`；不改 `targets.json` schema | 暂缓，M4 Profile 持久化/诊断需要时再评估 |

明确不吸收：

- Claude/Codex 会话 JSONL 探针：会读取 `~/.claude` / `~/.codex` 内容，超出 Argus
  “只观察用户选择窗口”的边界，隐私面过大。
- 远程通知/webhook/ntfy、浏览器扩展、伴侣 socket：MVP 不联网、不引入外部通道。
- `one-code` 的双形态状态机：VS Code 扩展与 desktop 的 `done` 语义不完全一致；
  Argus 继续只保留 `ArgusCore` 一套状态机。
- `minWorkDuration` 用于完成判定：会让短回复永远不 `Completed`；将来只可用于
  通知抑制，不改变检测真相。

复核触发条件：

1. 其余真实客户端 Profile 标定开始，需要区分确定性信号与推断信号时；
2. M4 诊断需要解释误判时；
3. 出现 OCR/AX 单信号拖垮整体置信度的实测案例时；
4. owner 明确要求借鉴，且先完成许可证审计。

在触发前，Argus 文档、代码和里程碑不把上述候选写成“已采用”。

## 4. 启动条件

- 首版支持哪些 macOS AI 客户端。
- 单次最多同时监控多少个目标。
- 多窗口/多实例时，卡片如何绑定并切换目标窗口。
- MVP 捕获延迟、完成检测误报/漏报、资源占用与多目标并发稳定性口径。
