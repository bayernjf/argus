# 06 — 测试与验收策略

- 版本：v0.1
- 日期：2026-11-22
- 状态：草案

## 1. 原则

- 核心逻辑不依赖真实窗口；状态机用纯单元测试。
- 真实捕获、权限、窗口切换必须手工/集成验证，不用 mock 冒充。
- 测试不得请求真实 AI 服务、不得上传屏幕内容、不得写入用户对话。
- 任何“完成检测通过”的结论必须附 fixture 或人工标注记录。

## 2. 测试层级

| 层级 | 范围 | 工具/方式 | 何时跑 |
|---|---|---|---|
| Unit | `ReplyCompletionDetector`、模型、Profile 解析 | `swift test` | 每次提交 |
| Contract | `CaptureSource` / `WindowActivating` / `PermissionManager` 协议 | mock 注入 | 每次提交 |
| Integration | 单窗口真实捕获、帧回调、缩略图 | 本地手工 + 脚本 | M1 起 |
| Manual UI | 多卡片、点击切换、权限、浅/深色、窄窗口 | 人工 | M2 起 |
| Soak | 3 目标 30 分钟 / 4 小时 | 本地 | M2/M4 |
| Privacy | 网络、落盘、日志脱敏 | 抓包/文件检查/日志抽查 | M1/M4 |
| Release | 干净机器安装、签名、公证 | 手工 | M5 |

## 4. 检测 fixture

M3 实现位于 `Fixtures/`，构建脚本 `scripts/build-m3-fixtures.sh`，产物只在 `build/fixtures` 下：

- `Fixtures/ArgusChatProbe.swift`：合成聊天窗口，AppKit，不联网、无用户内容。
- `Fixtures/PhaseSampler.swift`：通过 Accessibility 每 0.1 秒读取 Argus 卡片的可见 phase，只读。
- 三个验收 bundle：`com.bayernjf.argus-fixture-a/b/c`，窗口标题 `Argus Fixture A/B/C`；另有 D 供诊断。
- 事件日志只写 `launch / stream_start / last_text_change / stall_begin / stall_end / finish` 与时间戳，不写正文。

场景覆盖：

| 场景 | 行为 | 期望 |
|---|---|---|
| `normal` | 合成文本流式增长后移除 spinner/Stop | `Streaming → Settling → Completed`，且 finish→Completed ≤3s |
| `stall` | 文本冻结 3s，spinner 与 Stop 保留 | 不得提前 `Completed` |
| `stallAx` | 文本和 spinner 冻结 4s，只剩 enabled AX Stop | 必须保持 `Streaming`；隔离 AX 信号 |
| `static` | 已完成回复、无生成控件 | 全程 `Idle`，不得 `Completed` |
| `blink` | 已完成回复 + 闪烁光标 | 视觉噪声不得判成 `Streaming` 或 `Completed` |

结果（2026-11-22，0.1s 相位采样）：

- 正例：A/B/C 均 `Idle → Streaming → Settling → Completed`；finish 到首次 Completed 上界 A 2.072s / B 1.865s / C 2.220s。
- 负例：A `static` 全程 `Idle`；C `blink` 全程 `Idle`；B `stallAx` 在 4.002s 内始终 `Streaming`，stall 内无 `Settling`/`Completed`，stall 结束后才 `Settling → Completed`。
- 日志：`/tmp/m3-positive-phases.log`、`/tmp/m3-negative-phases.log`（临时证据，不提交正文）。
- 限制：合成 fixture 与豆包工作单客户端不能证明 ChatGPT/Claude/Cursor；其余客户端与 AX 增强留 M4。

fixture 只存必要的窗口区域帧或哈希指纹；不提交真实对话全文、用户名、密钥。

## 5. 手工验收矩阵

| 场景 | 期望 |
|---|---|
| 首次启动，拒绝屏幕录制 | 明确提示 + 系统设置入口；无崩溃 |
| 授予屏幕录制后选择 1 窗口 | 2 秒内首帧；卡片出现 |
| 3 个目标同时运行 30 分钟 | 卡片不串流；CPU/内存可接受 |
| 目标窗口最小化 | 卡片显示不可见/暂停；不显示旧帧冒充实时 |
| 目标应用退出 | 卡片显示 Window Closed；点击不激活错误应用 |
| 暂停目标 | 状态 PAUSED；最后一帧保留但不刷新；恢复后重新 LIVE |
| 窗口关闭后重新打开 | 同 bundle 唯一窗口时 10 秒级自动重建；多候选保持等待不猜 |
| 连接中立即暂停 | 最终停在 PAUSED，无 CAPTURE ERROR、无残留流 |
| 同一应用两个窗口 | 两张卡片；点击各自切到正确窗口；标题重复时拒绝选择并提示 |
| 目标窗口被其他窗口遮挡 | 捕获是否继续需记录；缩略图不得假装在顶层 |
| 多显示器 / Space 切换 | 状态可恢复；不崩溃 |
| 浅色/深色 | 状态文字可读，不只靠颜色 |
| 窄窗口 600px | 无横向溢出，卡片降为单列；状态条隐藏右侧提示 |
| 900px | 多列卡片与状态条正常，无截断 |
| 拒绝辅助功能权限 | 点击卡片只激活应用并提示授权；捕获/检测不阻塞 |
| 退出 Argus | 捕获停止；无残留进程/帧文件 |
| 抓包/代理 | 无主动外联 |
| 日志抽查 | 不含窗口正文、提示词、邮箱 |

## 6. 性能与稳定性

M4 记录：

- 2026-11-22 干净 4h soak：480 samples / 240 min；PID `81830` 全程不变；CPU avg 19.6%、median 18.6%、p95 30.9%、max 40.3%；footprint avg 143.8 MB、min 128 MB、max 159 MB、first 156 MB、last 148 MB；无崩溃。
- 相位采样 48 个：43 个有效，04:06–04:31 共 5 个 `NO_WINDOW`；Argus 和三个 fixture 进程仍活，窗口不可访问，未找到明确锁屏/显示睡眠日志。
- 诊断页实机：3 目标 `2.0 fps`，frame age 0.1–0.6s，detect 79–431ms；关闭 fixture A 后目标变为 `unknown / windowClosed / D03_UNKNOWN`，复制文本脱敏。
- 待补：1 目标 2 fps vs 1 fps 的差异；OCR 开启/关闭 CPU 差异；窗口关闭/重开 50 次；显示器休眠/唤醒、锁屏/解锁恢复。

建议门槛（草案，M4 实测校准）：

- 3 目标平均 CPU ≤ 8%（Apple Silicon）；
- 内存 ≤ 300 MB；
- 4 小时无崩溃、无持续内存增长；
- 单目标卡顿不影响其他卡片。

## 7. 隐私与安全验收

- 应用运行期间无主动网络请求；若未来有更新检查，必须可关闭。
- 不创建截图文件；临时目录抽查无窗口帧。
- 日志只含目标 id/状态/错误码/耗时；不含正文。
- 捕获帧在目标移除/暂停后释放。
- 受保护/DRM 窗口显示不可捕获，不尝试绕过。
