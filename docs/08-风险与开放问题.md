## 2. 开放问题

### 产品

1. 首版支持哪些 macOS AI 客户端？候选验证对象：ChatGPT macOS、Claude Desktop、Cursor；M3 已用 3 个合成 bundle 完成机制验收，真实客户端矩阵与是否接受合成 fixture 作为 M3 退出证据仍需 owner 拍板。
2. 是否提供“手动标记完成/仍在生成”作为检测反馈？
3. 中文显示名是否保留 Argus？
4. 目标卡片是否需要分组/搜索/排序？MVP 先不做。

### 技术

1. ScreenCaptureKit 对最小化、被遮挡、全屏、多 Space 窗口的行为；M2c 用 `CGWindowList .optionAll` 判断存在性，需 soak 确认最小化窗口仍被列出、不会被误判为关闭。
2. 是否需要 XPC/Helper 隔离捕获崩溃。
3. OCR 频率与 ROI 策略；多目标 CPU 是否可接受。M3 实测：0.5s 无条件 OCR 时 3 目标约 37.5% CPU；改为画面变化才 OCR + AX 1s 缓存后空闲约 11.7%。活跃 OCR 的完整 soak 留 M4。
4. 多显示器激活窗口的优先级。
5. macOS 27 的 Accessibility 授权提示形式与生效时点需实机确认。
6. 是否需要 App Sandbox；App Store 可行性。
7. `one-code` 可复用模块的依赖、许可证与测试。

### 发布

1. 是否上架 Mac App Store。
2. 内测分发渠道与签名凭证。
3. 是否做自动更新；MVP 默认手动。
4. BayJF `/products/argus` 产品页何时上线、需要哪些真实截图。

## 3. 已拍板

- 首版 macOS only；Windows 后续迁移。
- 产品内部名 Argus；Tier 2。
- Dashboard 多目标，每个目标一张卡；卡片有缩略图，点击切换。
- 本地优先；MVP 不联网、不落盘截图。
- 完成检测宁可 Unknown，不伪造 Completed。
- MVP 不单独建 `argus-landing`（ADR-008，Proposed，默认执行）。
- 单次最多 3 个监控目标；M4 soak 有数据后再评估放宽（ADR-011）。
- 重启恢复严格不猜：同 bundle 唯一可用窗口才自动绑定，多候选交回用户重选（ADR-011）。
- 首版客户端矩阵推到 M3 再定；M2 验收只要求任意真实窗口。
- 激活先匹配再激活；多候选或无候选不激活应用，AX 缺失只做应用级切换并提示（ADR-012）。

## 4. 复核节奏

- M1 结束：复核权限、捕获、app bundle 风险。
- M2 结束：复核多目标、窗口切换、持久化风险。
- M3 结束：复核检测准确率、Profile、fixture 覆盖。
- M4 结束：复核性能、隐私、稳定性；决定是否进入 M5。
- M5 前：复核分发、签名、App Store 决策。
