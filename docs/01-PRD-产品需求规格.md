## 1. 一句话

Argus 是一个 macOS 本地 Dashboard：同时观察多个目标软件的窗口，用一张张监控卡片显示实时缩略图和 AI 回复状态；点击缩略图切换到对应目标软件窗口。

## 2. 背景与问题

用户同时使用多个 AI 客户端（聊天、编码、写作、研究）时，常见问题是：

- 回复在多个窗口里流式输出，用户要来回切换才能知道哪一条已经结束。
- 某个回复结束了，但用户当前在另一个应用里，容易错过下一步操作。
- macOS 自带 Mission Control / Stage Manager 解决的是窗口布局，不解决“AI 回复是否结束”的语义状态。
- 现有工具要么只做窗口切换，要么只做单应用内的通知，缺少一个跨应用、低干扰的观察面板。

Argus 只做一件事：把“哪些目标窗口正在生成、哪些已经完成”变成一眼可见的卡片，并让用户从卡片直接回到目标窗口。

## 3. 产品目标

### 3.1 MVP 目标

1. 同时监控多个目标软件窗口；每个目标一张监控卡片。
2. 每张卡片显示目标窗口的实时小缩略图。
3. 判断卡片对应窗口里的 AI 回复是否已经结束，支持流式输出完成检测。
4. 点击卡片缩略图，切换到对应目标软件窗口。
5. 全程本地运行：不上传屏幕内容，不持久化截图，不依赖云端服务。

### 3.2 非目标

- 不做 Windows 首版；Windows 迁移后续单独立项。
- 不替代目标软件，不注入提示词，不读取或修改对话内容之外的产品状态。
- 不做通用窗口管理器、虚拟桌面或 Dock 替代品。
- 不做云端同步、远程监控、多人共享。
- 不做“AI 回复质量评分”或“回答对错判断”；只判断可见的生成状态。
- 不在 MVP 内做插件市场、脚本系统或第三方集成市场。

## 4. 用户与场景

### 4.1 目标用户

- 同时使用 2–6 个 AI 客户端的知识工作者、开发者、研究者。
- 需要长时间等待 AI 生成，但不想一直盯着某一个窗口的人。
- 在意隐私，不希望屏幕内容离开本机的人。

### 4.2 核心场景

1. **多任务等待**：在 ChatGPT、Claude、Cursor 各发起一个任务，回到 Argus Dashboard，看到哪张卡片还在 Streaming、哪张已 Completed。
2. **完成提醒**：某张卡片从 `Streaming` 进入 `Completed`，用户一眼看到，点击缩略图回到该窗口继续操作。
3. **临时离开**：用户去开会或做别的事，回来时通过卡片状态快速恢复上下文。
4. **多窗口同名应用**：同一应用开了多个窗口时，卡片按窗口区分，不把两个窗口混成一张卡。

## 5. 核心概念

| 概念 | 定义 |
|---|---|
| Target / 目标软件 | 用户明确选择要观察的一个应用窗口 |
| Monitoring Card / 监控卡片 | Dashboard 中代表一个目标窗口的卡片 |
| Thumbnail / 小缩略图 | 目标窗口的实时缩小画面，不持久化 |
| Reply Phase / 回复阶段 | `idle / streaming / settling / completed / unknown` |
| Dashboard | 承载多张监控卡片的主界面 |
| Target Profile | 针对某个应用/窗口类型的检测配置（区域、控件、信号权重） |

## 6. 功能需求

### FR-01 添加监控目标（P0 / M1）

- 用户从窗口选择器选择一个正在运行的目标应用窗口。
- 首次使用时引导授予“屏幕录制”权限；拒绝时显示可恢复的说明，不崩溃。
- 同一窗口不能重复添加；同一应用的不同窗口可以分别添加。
- 添加后立即创建一张卡片，并开始捕获。

**验收**：选择 1 个窗口后，Dashboard 出现 1 张卡片；权限拒绝时有明确提示和“打开系统设置”入口。

### FR-02 多目标 Dashboard（P0 / M2）

- Dashboard 以卡片网格展示所有正在监控的目标。
- 每张卡片独立显示目标名、窗口标题、缩略图、回复阶段、最近帧时间。
- 卡片数量变化不导致布局溢出；窗口变窄时自动降为单列。
- 支持至少 3 张卡片同时运行；最大数量待定（建议 MVP 先验证 3，硬上限可配置为 6）。

**验收**：3 个目标同时捕获 30 分钟，卡片状态互不串扰；布局在 900px 和 600px 宽度下不横向溢出。

### FR-03 实时缩略图（P0 / M2）

- 每张卡片显示目标窗口的实时缩小画面。
- 缩略图只保存在内存；默认不写磁盘。
- 目标窗口最小化、被遮挡或切换 Space 时，卡片要能显示“不可见/暂停”状态，不伪造正常画面。
- 缩略图刷新频率 1 fps、输出宽 448 px；这是 M4 三目标 CPU 实测后的正式值，不再沿用早期的 2 fps / 960 px 设计值。
- 刷新频率必须满足“内容变化后 1 秒内可见”，不得为了省 CPU 把帧率降到 1 fps 以下。

**验收**：目标窗口内容变化后 1 秒内卡片可见变化；最小化/关闭窗口时卡片状态在 2 秒内变为不可用或暂停。

### FR-04 AI 回复完成检测（P0 / M3）

- 对每个目标窗口判断“可见 AI 回复是否已经结束”。
- 支持流式输出的完成检测；检测到生成中时显示 `Streaming`，停止变化后先进入 `Settling`，稳定超过窗口后进入 `Completed`。
- 无法获得可靠信号时显示 `Unknown`，不得猜测 `Completed`。
- 首版使用通用检测；后续可为不同 AI 客户端加 Target Profile。

**验收**：在 fixture 集上达到 PRD §9 的延迟/误报/漏报草案指标；人工复核不出现“明显还在生成却显示完成”的高置信误判。

**M3 验收口径（2026-11-22）**：owner 接受“合成 fixture + 豆包工作真实视觉链路”作为 M3 退出证据；AX 增强与 ChatGPT/Claude/Cursor 标定延后 M4。

### FR-05 点击缩略图切换（P0 / M2）

- 点击卡片缩略图，将对应目标软件窗口切到前台。
- 同一应用多窗口时，优先激活卡片绑定的那个窗口，而不是随便激活一个窗口。
- 目标已退出或无窗口时，卡片显示不可用状态，不执行错误激活。

**验收**：3 个目标中逐个点击，90% 以上在 1.5 秒内切到正确窗口；目标退出后点击有明确失败提示。

### FR-06 卡片状态与新鲜度（P0 / M2）

- 卡片显示 `Idle / Streaming / Settling / Completed / Unknown`。
- 显示最近成功帧的时间；超过阈值未更新时标记为“画面过期”。
- 状态变化必须有视觉区分，但不能只靠颜色；同时提供文字标签。

**验收**：五种状态在浅色/深色模式下可区分；状态变化与检测器输出一致。

### FR-07 暂停、恢复、移除（P1 / M2）

- 用户可以暂停某个目标的捕获，卡片保留但显示 Paused。
- 可以恢复、移除目标；移除后释放捕获资源。
- 关闭 Dashboard 窗口不应静默继续录制；后台行为需在设置中明确。

**验收**：暂停后不再产生新帧；移除后 CPU/内存回落；重新添加可恢复。

### FR-08 目标列表本地持久化（P0 / M2）

- 记住目标的应用标识、窗口标题匹配规则和卡片顺序。
- 应用重启后按 bundle id + 窗口标题重新解析窗口；解析失败标记为“待重新选择”，不错误绑定其他窗口。
- 不持久化截图、OCR 正文或对话内容。

**验收**：重启 Argus 后目标列表恢复；窗口已关闭时显示待重新选择。

### FR-09 权限引导（P0 / M1）

- 屏幕录制权限：首次添加目标前解释用途，并提供系统设置入口。
- 辅助功能权限：仅在需要读取控件状态时请求；拒绝时降级为纯视觉检测。
- 权限状态变化要能热更新，不要求用户重启应用。

**验收**：两种权限分别拒绝/授予时，应用有对应状态与降级路径。

### FR-10 隐私与本地优先（P0 / M1）

- 默认不发起任何网络请求。
- 不把截图、OCR 文本、窗口标题写入日志之外的持久存储。
- 日志默认脱敏，不包含对话正文、提示词、邮箱等。
- 提供“暂停全部”“退出时停止捕获”的明确行为。

**验收**：网络抓包/代理观察无应用外联；日志抽查不含窗口正文；退出后无捕获进程残留。

### FR-11 诊断与可观测性（P1 / M4）

- 本地诊断页显示：捕获帧率、检测耗时、最近状态转换、错误码。
- 诊断信息不包含截图或正文；可导出为脱敏文本。
- 提供“复制诊断信息”按钮，方便用户反馈。

**验收**：能定位“没有帧 / 没有权限 / 检测 unknown / 激活失败”四类问题。

### FR-12 目标配置（P1 / M3–M4）

- 为不同应用配置检测区域、完成信号、窗口匹配规则。
- 配置以本地文件保存，不包含屏幕内容。
- 配置错误时回退到通用检测，不阻塞卡片。

**验收**：至少一个应用能通过配置提高完成检测准确率；配置损坏时安全回退。

## 7. 关键交互

### 7.1 首次启动

1. 展示一句话说明：Argus 只观察你选择的窗口，不上传内容。
2. 请求屏幕录制权限；解释为什么需要。
3. 打开窗口选择器；用户选择目标。
4. 生成第一张监控卡片；显示 `Streaming` 或 `Idle`。

### 7.2 日常使用

1. 用户从菜单栏/Dock 打开 Argus Dashboard。
2. 看到多张卡片；每张卡片有缩略图、目标名、阶段。
3. 某张卡片进入 `Completed`，用户点击缩略图。
4. Argus 激活对应窗口，用户继续操作。

### 7.3 失败路径

- 权限被拒：卡片显示 Permission Required，提供系统设置入口。
- 窗口关闭：卡片显示 Window Closed，保留配置，等待重新选择。
- 捕获不到内容：显示 No Frame，不显示旧截图冒充实时。
- 检测信号不足：显示 Unknown，并允许用户手动标记“已完成/仍在生成”作为反馈（P1）。

## 8. 回复完成判定

### 8.1 定义

“完成”指：目标窗口中可见的 AI 回复在一段稳定窗口内不再变化，并且没有可见的“正在生成/停止生成”指示。它不是对模型内部状态的断言，也不是对回答质量的判断。

### 8.2 信号

首版按多信号融合设计，按可用性降级：

| 信号 | 用途 | 备注 |
|---|---|---|
| 帧差 / 文本稳定性 | 判断画面是否还在变化 | 通用、无需辅助功能权限 |
| OCR 文本变化 | 判断回复文本是否停止增长 | Vision 本地识别，不联网 |
| 生成中控件 | 检测 Stop / Generating 指示 | 优先 Accessibility，失败时用视觉模板 |
| Accessibility 文本 | 读取静态文本与按钮状态 | 需要辅助功能权限，作为增强信号 |
| 应用 Profile | 指定检测区域/控件 | 解决不同客户端 UI 差异 |

### 8.3 状态机

```text
idle
  └─ 检测到生成 ──> streaming
streaming
  └─ 画面/文本停止变化 ──> settling
settling
  ├─ 稳定超过 settleDuration ──> completed
  └─ 再次变化 ──> streaming
任意状态
  └─ 信号不可用/冲突 ──> unknown
```

实现位于 `Sources/ArgusCore/Detection/ReplyCompletionDetector.swift`。UI 层不得绕过状态机直接把卡片标成 Completed。

### 8.4 置信与误判

- 高置信才显示 `Completed`；中低置信显示 `Settling` 或 `Unknown`。
- 对“长时间无变化但仍在生成”的应用，Profile 可以延长 settleDuration 或要求 Stop 控件消失。
- 任何“完成”误判都要能回放到具体帧序列；M3 建立 fixture 与人工标注集。
- 首版宁可漏报（显示 `Unknown`）也不要把仍在生成的回复标成完成。

## 9. MVP 验收口径（草案，待实测校准）

以下为建议值，不是已承诺的 SLA；M1/M3 实测后由 owner 确认。2026-11-22 owner 接受“合成 fixture + 豆包工作真实视觉链路”作为 M3 验收口径；AX 增强与其余客户端标定延后 M4。

| 指标 | 建议口径 |
|---|---|
| 同时监控 | 3 个目标稳定运行 30 分钟；硬上限可配置 |
| 缩略图刷新 | ≤ 1 秒可见更新 |
| 完成检测延迟 | 最后可见变化后 ≤ 3 秒进入 Completed（高置信场景） |
| 完成误报 | 人工标注集上 ≤ 5% |
| 完成漏报 | 人工标注集上 ≤ 10%，允许显示 Unknown |
| 点击切换 | 90% 目标在 1.5 秒内切到正确窗口 |
| CPU | Apple Silicon 上 3 目标平均 ≤ 8%（M4 最终 4h：5.92%，P95 6.80%、max 7.30%） |
| 内存 | 3 目标 ≤ 300 MB（待实测） |
| 网络 | 应用运行期间无主动外联 |
| 持久化 | 不落盘截图/OCR 正文 |

## 10. 非功能需求

- **隐私**：本地优先；最小权限；用户可暂停/移除；日志脱敏。
- **性能**：捕获和检测不能拖垮目标应用；按目标限流、丢帧而不是无限排队。
- **可靠性**：权限变化、窗口关闭、显示器休眠、Space 切换都要有可恢复状态。
- **可访问性**：卡片状态不只靠颜色；支持键盘聚焦和 VoiceOver 标签。
- **可维护性**：检测逻辑与 OS 捕获解耦；新增应用 Profile 不改核心状态机。
- **可测试性**：核心逻辑不依赖真实窗口；fixture 可回放。

## 13. 风险摘要

- 不同 AI 客户端 UI 差异大，单一检测器容易误判。
- ScreenCaptureKit 对受保护内容、最小化窗口、Stage Manager 的行为需要实测。
- Accessibility 权限门槛高，不能把它作为唯一信号。
- 多目标捕获可能带来 CPU/内存压力。
- 点击切换在多窗口/多显示器下可能激活错窗口。
- 屏幕内容本身可能包含敏感信息，隐私设计必须先于功能扩张。

完整清单见 `08-风险与开放问题.md`。
